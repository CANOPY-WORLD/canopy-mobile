01 / Architecture

Three components.
One scenario to connect them.

Scenario is the declaration: where the work happens, which assets belong to it, which methods to run, and how to view the result.

Model runs. Geometry tools and physics simulators share the same Method lifecycle.

Asset records. Geometry and physics results are versioned data owned by their Scenario.

Visualizer reads. A shared shell displays both geometry and results. Scenario presets adjust presentation.

Reusable methods, explicit ports.

Geometry → solar, flood or wind. Temperature and pollution also read wind results. Select a Method to inspect its interface and open its run guide.

The imported Physics4D research code is also retained under model/src/. A source file becomes a supported Method only after registration, validation and a run guide.

Two asset kinds. Exact versions.

Geometry bundles hold display meshes and computational representations. Physics bundles hold recorded fields, clocks, masks and provenance.

Asset / purposeLayers & unitsEncodingRecorded samplesBundle size

Bundle sizes include descriptors and provenance. “Verification” assets belong to the same London Scenario and are not selected in its default view. Historical run clocks are independent; relative display alignment does not establish physical synchronization.

A fixed frame, with small variations.

One template owns camera, time and layer state. Widgets interpret supported data. Presets change presentation without moving simulation code into the browser.

A practical format stack

JSON
Scenario, Asset descriptors, manifests, timestamps, entity IDs and provenance.
GLB
Geometry for loading and display. Solvers request a declared heightfield, grid or native representation separately.
NPY
Typed numerical arrays. Use frame indexes for time series, with explicit axes, units, masks and real sample times.
Zarr Future
A candidate for large 3D time series and spatial subset reads. It needs a new codec, validator and reader before adoption.

Current storage choice

One shared Viewer.
A data home for each Scenario.

London’s 1,477 public files occupy about 558 MB in their own repository. Canopy's publication reference pins the source revision, snapshot URL and manifest hash.

The main website packages the Viewer, this guide and small indexes. Adding a Scenario does not add its payloads to the main site's publication budget. Each data site still has its own 1 GB Pages limit.

04 / Extending Canopy

An entry point for every change.

Agents and people follow the same component standards. Start with the contract, implement the interface, verify the behavior, then refresh the inventory.

All component standards ↗

Each component includes AGENTS.md, CONTRIBUTING.md and a focused README.md.

describe→validate→prepare→execute→export

The shared runner validates and retains the export before registering an Asset.

Creating a new Scenario? The Scenario contributor guide includes a runnable isolated example, data contracts, publication steps and a PR checklist. New public cases need an explicit admission PR; the curated catalog currently contains London only.
